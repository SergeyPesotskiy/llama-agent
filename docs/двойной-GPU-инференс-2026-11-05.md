# Запуск нейросети на двух GPU: исследование субагентом + верификация (2026-11-05)

Процесс и результат получены «нашими же агентом и субагентом»: задача исследовала
двух-GPU инференс-станцию внутренней сети, мозг субагента был вынесен на отдельную
нейросеть через пул `--subagent-backends` (ветка `subagent-backends`).

## Как это делалось (процесс)
1. Главный агент (модель A) по команде создал субагента с `task backend=0`,
   субагент выполнялся моделью B с GPU-станции (подтверждается строками лога
   `[subagent general] inference backend: http://<станция>:8080`).
2. Первая попытка «дай субагенту команды SSH» оказалась ненадёжной: модель B
   плохо держала инструментальный цикл (часть вызовов возвращала пустой текст,
   одна попытка выдумала «нет сети»). Попутно нашлась и настоящая причина отказа
   доступа: на станции `authorized_keys` имел права 0664 — sshd StrictModes его
   игнорировал; исправлено на 0600.
3. Надёжная схема: инструментальные данные собирает основной агент, а модель B
   **анализирует** готовый срез (всё, что у слабой к инструментам модели хорошо
   получается — рассуждение по тексту). Так и сделали.

## Верифицированные факты (собраны пробниками с самой станции)
- Сервер: python-обёртка `serve/server.py --engine <движок> --config qwen36.json`,
  дети: `*-vision` (mmproj-F16) и инференс-движок `--serve --model
  Qwen3.6-35B-A3B-UD-Q5_K_XL.gguf --max-context 4096 --expert-slots 4
  --expert-slots1 64 --layer-split auto`.
- Железо: 2× AMD Radeon RX Vega 56/64 (gfx906), **по 8 ГБ HBM2 каждая**
  (`mem_info_vram_total` ≈ 8.57 GiB).
- Фактическое потребление: card0 8.54/8.57 GiB (**~99.6 % — почти заполнена**),
  card1 6.5/8.57 GiB (~76 %).
- Вес файла модели: 25.3 GiB > 17.1 GiB суммарной VRAM ⇒ часть весов
  (MoE-эксперты, судя по `--expert-slots*`) resides в оперативной памяти;
  слои разложены по обеим картам (`--layer-split auto`).
- Окружение инференс-процесса: `HIP_VISIBLE_DEVICES=0,1` (обе карты),
  `HSA_FORCE_FINE_GRAIN_PCIE=1` (важно для скорости CPU-offload на gfx906),
  `HSA_ENABLE_SDMA=0` (обходнойknown workaround для Vega).
  `HSA_OVERRIDE_GFX_VERSION` **не задан** (не нужен: gfx906 нативен ROCm).
- Мониторинга нет: `/opt/rocm/bin` без `rocm-smi`/`rocminfo`; единственный
  источник телеметрии — sysfs `amdgpu`.

## Отчёт модели B (субагента) — с правками проверяющего
Модель B корректно определила: стек обслуживания, факт разложения по двум картам
(`layer-split auto`), догадку про expert placement, рекомендацию поставить
rocm-smi и контролировать VRAM-запас. Ошибки, исправленные верификацией:
размер карт принят за 16 ГБ («50 % заполнено») — фактически 8 ГБ и card0 почти
полная; «HSA_OVERRIDE установлен» — не установлен; про fine-grain PCIe/SDMA
не упомянуто, хотя это ключевые для стабильности флаги.

## Выводы
- Двух-GPU инференс **активен штатно**: слои по обеим картам, часть MoE в RAM,
  картинка нагрузки соответствует `layer-split auto` на картах с дефицитом VRAM.
- Главный риск — **VRAM card0 на пределе (99.6 %)**: рост контекста/второй слот
  дадут OOM или своп; держим `--max-context 4096`, следим sysfs-ом.
- Стоит добавить: `rocm-smi` в контейнер/систему (или экспортёр из sysfs),
  алерт на `mem_info_vram_used > 0.95 * total`.
- Методологический вывод по агентам: для моделей со слабым tool-use субагентов
  использовать паттерн «данные собирает диспетчер — модель анализирует»; чистый
  «субагент с инструментами у слабой модели» ненадёжен и жжёт токены.
